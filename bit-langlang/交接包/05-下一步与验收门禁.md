# 05 下一步与验收门禁

## 1. 当前阶段的定义

**阶段：paper/前瞻验证期，不是实盘期。**
- 平台代理 A：已通过回测关，正在 paper 跑；
- 本地 TPH v2：参数冻结，等 risk_on 信号；
- 真实资金：**0**。

## 2. 每日监控清单（约 5 分钟）

1. 更新数据（BTC/ETH）：
   `python3 scripts/02_download_market.py --symbols BTC ETH --intervals 5m 1d`
2. 平台状态：
   - `traders list` 确认代理 A 仍 running；
   - `positions` / `account-status` 记录 equity、持仓、浮盈亏；
   - `strategy-billing` 确认仍为 included、$0/h、无 PAYG。
3. 本地 TPH：
   - `python3 -m verify.forward_scan --days 3` → 看 risk_on / watch / signals；
   - 有信号才按 `verify.log` 记录纸面。
4. 把当日状态追加到日志（建议 `data/verify/forward_daily.md`）。

## 3. 代理 A 的事件应对

| 事件 | 动作 |
|---|---|
| BTC 日线收盘 < SMA120（≈74,155） | 策略自动平仓 → 确认成交、记录离场价/盈亏；之后空仓等下一次上穿 |
| BTC 日线重新上穿 SMA120 | 策略自动开仓 → 确认持仓 |
| 平台策略被停/异常 | 先查 runtime/events；**不要盲目 restart**（free 订阅无 slot，重启可能失败）；报告用户 |
| 订阅恢复/升级 | 记录日期，评估是否恢复 paper 槽位 |

**代理 A 的弃用条件（预注册）**：连续 3 次完整交易（入场→离场）净亏损，或权益从高点回撤 > 25% → 停跑并复核；不允许中途改参数。

## 4. 本地 TPH v2 前瞻验证（核心）

- 冻结参数：`verify/frozen_config.json`；协议：`docs/前瞻验证方案.md`。
- 记录：`python3 -m verify.log add ...`；判定：`python3 -m verify.forward_report`。
- 预注册门槛（`forward_report` 自动判）：
  - 任何纪律违规 → **STOP**；
  - ≥20 笔且平均 R < −0.2 → **STOP**；
  - ≥90 天 且 ≥20 笔 且 平均 R >0 且 成本/毛利 ≤30% → **PASS**（可小资金）；
  - 其他 → **HOLD**（继续，不改参）。
- PASS 之后：0.5% 风险小资金再跑 3 个月；期间不允许改参。

## 5. 任何新策略/新代理的"回测关"（预注册）

1. 全样本收益 > 0；
2. 冻结样本外收益 > 0；
3. 样本外 MDD ≤ 40%；
4. 样本外 Sharpe > 1.0；
5. 无爆仓；
6. 样本外交易数 ≥ 10。

**六条全过才算 PASS。** 新想法先写配置、跑回测、记录结果，不许直接上 paper。

## 6. 明确不许做的事

1. 不许投真实资金、连真实交易所、充值、付费、升级套餐；
2. 不许创建第 6 个 running paper（free 订阅无 slot，会触发付费失败）；
3. 不许动用户现有 4 个模拟研究（BTC空网格/SOL多网格/ETH空网格/UNI马丁）；
4. 不许因为短期盈亏改参数（过拟合）；
5. 不许把代理 A 的结果当成 TPH v2 的证据；
6. 不许在报告里写账户 ID/token。
