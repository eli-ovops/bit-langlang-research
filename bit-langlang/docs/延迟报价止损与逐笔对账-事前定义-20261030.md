# 延迟报价止损与逐笔对账：事前定义（2026-10-30）

状态：合成研究候选；未注册正式前瞻，也不修改原冻结规则。止损在这里只是离散观察下的模拟判断，不是已提交的交易所委托。

- 已记录入场价格乘以 0.996 为未取整的价格止损；先采用完整的信号、入场报价和入场事件的研究检查。
- 入场事件采集后，请求一份独立公开一级报价；如果该报价 bid 不高于止损，随后将该 bid 保存为同交易编号的 mark 事件。本研究把它称为 bid 观察，不是交易所标记价格，也不能证明这是第一次触及止损。
- mark 事件采集后再请求一份独立报价，再记录同编号 exit；纸面多头出场价为新 bid × (1 − 0.0002)。报价时间、时钟和因果顺序沿用延迟入场的事前阈值；数量大于卖一 bidQty 时结果 UNKNOWN，即便不足一级数量也不证明成交。
- 对每笔单独计算：入场与出场名义额各乘 0.0005 得假设手续费，已记录的有符号资金费正数为支付、负数为收到；净盈亏 = (出场价 − 入场价) × 数量 − 双边手续费 − 资金费，净 R = 净盈亏 / ((入场价 − 止损价) × 数量)。买卖价自身已体现点差，滑点已计入成交价，不再重复扣。资金费数值由外部提供，完整性仍需单独核验。
- 行情未连续观察、止损发生在两次快照之间、一级订单变化、真实委托类型、价格精度、强平与资金费均未被证明。bid 触发不同于原回放中 5 分钟最低成交价代理，因此仅为新候选，不得同原回测混算。离散报价结果不足以证明触发时间或最坏损失；[CFTC 提示](https://www.cftc.gov/LearnAndProtect/AdvisoriesAndArticles/fraudadv_tradingsystem.html)指出止损可能以不同价格成交或无法成交。
- 合成测试应覆盖完整链路、未触止损、报价倒序、编号不匹配、超出 bidQty、出场价错误、资金费正负、与原净 R 报告的数值对账；合成数据不得算作真实前瞻。

## 工具

使用 `python3 -m verify.paper_quote check-round-trip --signal <信号事件> --entry <入场事件> --entry-quote <入场报价> --mark <bid触发观察事件> --trigger-quote <触发报价> --exit <出场事件> --exit-quote <出场报价> --qty <数量> --funding-cost <有符号资金费> --as-of <UTC检查时间>` 可对三次报价和四个事件做形式对账；输入文件 SHA-256 随结果列出。符合条件最多返回 `PARTIAL_NOT_REGISTERED`，一级数量不足为 `UNKNOWN_DEPTH`。资金费由调用者输入，结果始终标记 `funding_verification: UNKNOWN`；另用资金费对账工具审查结算明细和覆盖，不能把参数填零当作未发生资金费的证据。该工具不验证连续报价、交易所的真实委托或账户状况。
