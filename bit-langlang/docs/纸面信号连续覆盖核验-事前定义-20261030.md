# 纸面信号连续覆盖核验事前定义

目标是对已保存的多次扫描和人工事件检查可追溯的时间覆盖，不启用定时任务、平台策略或实际前瞻。每次扫描需保留原始扫描 JSON、与其 SHA-256 匹配的 BTC/ETH 5 分钟行情快照和在文件保存后记录的本机回执。扫描生成时间是计算开始时间，不能当成文件已可用的时间；扫描间隔与候选首次可见时间使用回执时间。文件及本机时钟均未被独立认证；即使格式检查通过，也不能证明过程未中断、数据未被修改或真实成交。

- 给定实际 UTC 起点（5 分钟网格）、检查终点和按回执时间排列的扫描。首条回执须在起点后 5–6 分钟内，以便首根 5 分钟 K 线已经收盘；连续两条回执间隔及终点距最后一条不得超过 6 分钟。6 分钟是候选研究阈值，不是保证交易可执行；缺失、重复、乱序、超时或尚无扫描均明确报告。
- 每次扫描验证冻结配置哈希、扫描回执、行情快照哈希、BTC/ETH 已收盘数据的新鲜度、连续性、OHLC 与重算候选；最近已收盘 K 线距本机回执不得超过 6 分钟。相邻快照共同覆盖的冻结历史价格须一致，变化即中止核查；记录无法证明数据提供方真实或服务器时间准确。
- 为允许人工记录，在每次扫描中只将生成时间减 15 分钟并向下取整到 5 分钟的时间作为已封存的**K 线收盘水位**。各扫描从上次水位接续，只核对该段候选；对应 signal 和 entry/skip 须唯一、按先后采集，最晚在该 K 线收盘后 15 分钟内记录。最新水位之后即使没有报错也必须列为未封存，不得称为完整覆盖。
- 每个已封存候选必须在它收盘后 6 分钟内出现在某次已验证扫描中；扫描候选被静默删除或数据滞后不能补称成功。若开始时刻、封存水位或数据窗口不足，返回 PENDING/UNKNOWN；缺少已封存事件、行情矛盾或参数不符返回 INVALID；时间顺序不明返回 AMBIGUOUS。延迟入场继续标 `EXECUTION_MODEL_MISMATCH`，不得冒充原次根开盘模型通过。
- 结论最多 `PARTIAL_COVERAGE_UNVERIFIED`，清楚显示信号、入场/跳过数、首末生成时间、最长间隔、封存水位及未封存时长；不等于连续盘口覆盖、可靠止损、资金费或账户完整。不能用离线合成记录冒充真实前瞻。
- 验证合成的正常接续、空档、扫描重复/未来、事件晚采/缺失/重复、未封存候选、行情篡改和跨快照矛盾；原单快照 API 的默认行为保持不变。

## 文件入口与实际限制

清单中 `scan` 和 `market_dir` 路径相对清单文件；每个行情目录需保存当次扫描对应的 `BTCUSDT_5m.csv.gz` 与 `ETHUSDT_5m.csv.gz`，而不是一个后来不断覆盖的目录：

```json
{"schema":"paper-scan-coverage-v1","scans":[
  {"scan":"scan-001.json","market_dir":"market-001","receipt":"receipt-001.json"},
  {"scan":"scan-002.json","market_dir":"market-002","receipt":"receipt-002.json"}
]}
```

扫描文件保存后可运行 `python3 -m verify.paper_scan_receipt --scan <扫描JSON> --market-dir <当次行情目录> --out <不存在的新回执JSON>`，在读取并核对扫描和行情哈希后以当前本机时间生成回执；回执写入本身及本机时间都没有独立认证。再运行 `python3 -m verify.paper_scan_coverage --manifest <清单JSON> --events <事件目录> --start <UTC起点> --as-of <UTC检查时间>`。保存与否由调用者决定；程序本身不会创建观察任务。跳过记录应提供非空、非 UNKNOWN 的原因，同一交易编号不得跨不同信号重复。未封存的事件与尚未在扫描中出现的事件单列，不能当作已核对。

当前实现为离线验证原型：每条扫描都需提供足够长、不可变的双币历史快照并重复验证。长期保存和重算的磁盘、时间开销尚未评估，不能直接宣称适合 90 天连续运行；可复用的数据增量方案与持续采集可靠性仍需另行设计和验证。
