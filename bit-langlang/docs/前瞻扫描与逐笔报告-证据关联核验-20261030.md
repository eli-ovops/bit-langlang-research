# 前瞻扫描与逐笔报告：证据关联核验

批量逐笔报告增加标准 UTC 观察起止时间。新增 `verify.paper_evidence_link` 检查扫描归档报告和批量报告的时间、事件文件哈希及批量扫描哈希是否一致，并报告归档锚点状态、未封存时长及组件状态。缺字段或扫描归档未完整重建、缺锚点时不能得到局部关联结论；时间、事件或扫描内容不一致返回 INVALID。报告 JSON 的重复键及非有限常量被拒绝。

合成测试覆盖 UTC 等价表示、时间及哈希不匹配、空证据、扫描重建或锚点不足、路径缺口、STOP 与执行模型不匹配优先级，以及命令行输入哈希。另将真实批量命令在合成账本上输出的时间和哈希，与模拟的扫描报告关联：缺少已平仓路径时，形式关联可以匹配，整体仍为 UNKNOWN。这个模拟的扫描报告不是实际归档审计，不证明连续观察。

两份报告、来源和锚点仍未独立认证；用户没有启动新前瞻或平台策略。使用方式和边界见[关联定义](前瞻扫描与逐笔报告-证据关联定义-20261030.md)。

后续增加七周期合成端到端演练：用模拟行情运行扫描并以实际本地归档模块保存，包含一次模拟归档中断及恢复；对同一组事件运行 `paper_scan_archive audit` 与 `paper_exit_batch` 两个真实命令，再关联它们的实际输出。两份报告的时间、事件与扫描哈希形式一致，但由于没有模拟入场，批量报告为 `NO_ENTRY_EVIDENCE`，关联总状态仍为 `UNKNOWN_INCOMPLETE`；最新扫描区间仍未封存。这比人工构造报告更能验证模块接线，仍不能证明真实行情、真实连续运行或 90 天容量。

同一合成演练进一步加入一笔延迟报价入场及 bid 止损：入场假设价 100.12002，出场假设价 99.48010，数量 1；按每边 5bp 计算合计手续费 0.09980006，合成资金费快照为空且覆盖持仓结算边界，净亏 0.73972006 USDT，初始价格风险 0.40048008 USDT，净 R 约 -1.847083。逐笔批量报告与独立算式一致，离散持仓路径和资金费检查分别为 `PARTIAL_DISCRETE_UNVERIFIED` 和 `PARTIAL`。归档审计和批量报告使用同一组合成事件，哈希形式关联匹配；由于延迟入场与冻结的下一根开盘模型不同，关联总状态正确显示 `EXECUTION_MODEL_MISMATCH`，最新扫描尾段仍未封存。

这是一笔完全合成的账本、报价、回执和资金费快照，不是实际订单、真实账户记录或真实行情；测试不证明连续盘口、真实资金费、实际成交、完整前瞻或 90 天运行可靠性。
