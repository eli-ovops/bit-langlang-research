# 扫描归档：原始响应增量对账结果

新增离线 `verify.paper_scan_source_reconcile`：依次恢复归档行情，从第二条提交开始，使用前一份快照和本次保存的服务器时间、两币 K 线响应重放采集器的增量处理，比较生成的 CSV 字节与当前归档行情；同时核查分页参数、请求顺序及请求与扫描时间关系。它不发网络请求。

七周期合成端到端演练中，**后续 6 次增量均匹配**；第一条采集前基线未包含在原归档结构中，明确标为 `UNKNOWN_INITIAL_BASELINE`，整体最多 `PARTIAL_SOURCE_REPLAY`。单步合成测试验证行情字节、请求分页参数或扫描时间被改动时会拒绝。重放复用生产采集器的 `load_base` 和 `advance`，不是独立实现，因此只证明有限的本地一致性。

后续新归档已可绑定首条采集前基线，新的七周期合成演练七次过渡均可重放；旧归档依然未知，详见[首条基线保全](扫描归档-首条采集基线保全-核验结果-20261030.md)。

对既有单次公开预检的旧归档做只读检查：它有 1 条旧提交，原始响应未绑定到提交内，且没有可比较的前后两份归档快照，结果为 `UNKNOWN_SOURCE_MISSING`；原输出目录中的请求原件仍单独保留，未被修改。

使用方式：

```sh
python3 -m verify.paper_scan_source_reconcile --archive <归档目录> --expected-head <预期头部SHA256>
```

预期头部如来自同一台机器的同一目录，仍不是独立可信锚；响应、行情来源、服务器与本机时钟、真实成交和连续盘口均为 UNKNOWN。工具不会启动采集、创建任务或操作平台策略。[核对定义](扫描归档-原始响应增量对账定义-20261030.md)
