# 扫描归档：公开原始响应保全

此前本地扫描归档保存扫描 JSON、回执及两币行情的完整字节或差量，但不包含采集时公开 REST 请求记录与响应正文。清理每次输出目录会丢失这部分证据，不能仅凭旧归档声称保全了完整采集原件。

现 `paper_scan_once` 在追加新归档时，将公开服务器时间、BTC/ETH K 线请求及响应正文一并保存到对应提交目录；提交记录对每个原文件绑定 SHA-256。追加前检查文件名、分页连续、请求与响应成对、请求中的正文哈希、接口和基本时间字段；查看归档记录时复查这些文件，恢复单次快照也会还原绑定的公开原件。旧调用仍可不带原始响应追加，但会标记 `UNKNOWN_NOT_CAPTURED`。原始文件与哈希匹配只证明本地内容一致，**不认证交易所来源、时钟或行情转换的正确性**。

旧归档不会被改写。只读检查 `data/verify/one-shot-preflight-20261030-01/archive` 显示 1 条旧提交、0 条归档内绑定的公开原件；其原始预检输出目录下仍有 6 个配对的请求与正文文件，当前格式和正文哈希可对上。它们没有自动并入旧提交链，来源与时间仍未独立认证，不得因新功能将旧归档标成已绑定。

合成测试覆盖旧格式读取、公开原件保存与恢复、文件缺对时拒绝提交、归档原件被修改时拒绝核验，以及 7 个合成周期的归档审计。扫描报告与逐笔报告的关联工具在尝试给出局部关联状态时，现还要求各扫描提交均绑定公开原件；旧报告或旧归档缺少该证据时仍为 UNKNOWN，不影响已有 STOP 或执行模型不匹配的提示。

该变更新增归档文件和 `fsync`，此前[24 周期空间和耗时测量](二十四周期合成扫描归档-测量结果-20261030.md)发生在此变更之前，不能作为新版本的完整开销数据。本次未删除任何用户已有扫描输出，未启动任务或平台策略。
