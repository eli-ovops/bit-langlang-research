# 扫描归档：首条采集基线保全

新归档首次采集时，`paper_scan_once` 已将采集前读取的 BTC/ETH 原始行情字节一并保存到首条提交，并将两份哈希绑定在提交记录中；采集过程原有的源文件前后哈希检查仍保留。查看归档和恢复首条快照时会核对基线哈希，并可在恢复目录内取得两份基线文件。内容或目录被修改时拒绝核验；旧归档缺少该基线仍标 UNKNOWN，不改写旧提交。

离线原始响应重放现在可以用这份基线检查首条行情增量。七周期合成测试中，**首条及后续六条共七次过渡均在本地字节上匹配**；结果仍为 `PARTIAL_SOURCE_REPLAY`、首条为 `MATCHED_UNVERIFIED`，因为重放复用采集器代码、来源和时钟均未认证。单元测试覆盖基线保存、恢复、篡改拒绝、原始响应篡改与旧归档兼容；原有单次公开预检的旧归档再次只读检查仍为 `UNKNOWN_SOURCE_MISSING`、初始基线 UNKNOWN。

扫描与逐笔报告关联的局部条件要求归档标明首条基线已绑定。后续已增加可选独立交叉核验报告作为第三项输入；关联工具不会自行运行该检查，未提供报告时仍为 UNKNOWN，详见[三份报告关联](前瞻三份报告-独立行情核验关联-20261030.md)。新功能会多保存一份初始行情，旧的磁盘和耗时样本不包含这一开销；实际连续运行与 90 天容量仍未验收。本次没有修改旧归档或启动平台策略。
