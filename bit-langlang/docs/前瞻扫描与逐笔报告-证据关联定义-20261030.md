# 前瞻扫描与逐笔报告：证据关联定义

目标是检查已生成的离线连续扫描归档报告与批量逐笔报告是否指向相同的 UTC 起止时刻、同一组事件文件内容及同一份已列入扫描序列的扫描文件。批量报告记录 `observation_interval`，其 CLI 的 `input_sha256.events` 和 `input_sha256.scan` 与扫描归档 audit CLI 的 `event_sha256` 和 `scans[].scan_sha256` 比较。缺字段、事件为空或报告不完整标 UNKNOWN；时间、事件、扫描不一致标 INVALID。该关联不使用网络，不创建观察任务或策略。

两份报告是调用者提供的本地数据，可能被修改或伪造；字段与哈希匹配只是形式关联，不是独立来源认证、可信时钟、不可回填证明或真实成交。单次扫描哈希属于归档列表也不证明某笔交易实际读取该扫描，且信号的首次可见时间、连续盘口、止损、资金费、未平仓及账本完整性仍须各自核验。归档水位以后的时间未封存，不能报告完整覆盖。

保留两份报告原有状态与缺口；STOP、INVALID 和执行模型不匹配不得被包装为成功。只有形式字段一致且两侧均处于明确的局部未验证状态时才能标 `PARTIAL_LINK_UNVERIFIED`，且不能被解读为 PASS 或允许实盘。延迟报价候选和冻结下一根开盘模型仍不一致；不可用此关联替代新执行版本注册与历史对照。

`verify.paper_evidence_link` 读取已经分别保存的 `paper_scan_archive audit` 和 `paper_exit_batch` JSON 报告：

```sh
python3 -m verify.paper_evidence_link --coverage <扫描归档报告JSON> --batch <逐笔批量报告JSON> --source-check <独立行情核验JSON>
```

结果写到标准输出，不创建或覆盖报告。局部关联还要求扫描归档报告显示全部扫描已重建、提供了外部预期头并与之匹配；该锚点本身仍未独立认证。未提供锚点或重建不全为 UNKNOWN；即便局部关联成立，`unsealed_seconds` 和组件状态都保留，不能称完整覆盖。旧批量报告缺起止字段时为 UNKNOWN，需以同一数据重新运行本地检查后再关联，不可手填时间伪造回执。

后续补充：局部关联还要求每条扫描提交均绑定公开请求、原始响应及首条基线，并另提供同一归档头部的独立行情交叉核验报告；旧归档未内置证据或未提供核验报告时标 UNKNOWN。绑定不认证来源或交易所数据。[三份报告关联](前瞻三份报告-独立行情核验关联-20261030.md)
