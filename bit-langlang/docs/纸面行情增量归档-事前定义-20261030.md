# 纸面行情快照增量归档：事前定义

目的：在不改动原始扫描、行情和回执的前提下，研究如何减少重复保存的空间，并验证中断后能否恢复到已提交状态。归档只处理本地既有文件，不采集行情、不启动定时任务或策略、不下单。

- 第一个检查点保存两份原始压缩行情文件；后续记录按固定 4 KiB 块比较同一币种的前一份和当前份，保存可复用的字节区间和变化字节。差异大时允许退化为完整保存。无论数据能否压缩，恢复的字节数和 SHA-256 都必须与对应原始文件完全一致，不重编码、不用近似数值替代。
- 每次记录原样保存扫描 JSON 和本机回执，验证其配置哈希、扫描文件哈希、行情文件哈希、生成/回执顺序；记录序号、前一个提交的 SHA-256、扫描/回执哈希和两币原始文件哈希。链条只能说明提供的文件相互一致，不认证交易所来源、本机时钟或内容真实，也不能凭链条自身证明没有被整体重写。
- 提交按新目录写入并刷盘，完整的提交记录使用同文件系统的原子硬链接以互斥方式发布；已有提交不会覆盖。中断时只保留尚未提交的临时运行目录，已发布提交仍须完整可读；恢复/再次尝试不得清理或覆盖已有文件。若文件系统不支持原子硬链接，显式失败并保留证据，不换通道绕过。
- 追加时调用方提供前一序号、前一提交哈希及前一份原始行情路径；先核对该哈希与前一份行情的原始文件哈希，拒绝分叉或错用历史。追加只核验前一头部，完整链条须另行检查；如需检测尾部截断，调用方必须提供先前在别处保存的预期头部哈希，不能把归档自己的头部称为外部锚定。
- 验证器按序核实链和每个字节差量，依次恢复行情，逐条核对原扫描和回执，并通过既有连续覆盖检查；只允许在任务私有临时目录逐条重建，不覆盖用户原件。最新封存尾段、数据真实性、真实成本及监控中断仍须独立报告。实际耗时和磁盘节省只报告真实测试样本，不外推 90 天可用性。
- 合成测试涵盖变化字节、完全不同文件、零增长、缺失/损坏文件、序号或前一哈希错误、重复提交、中断残留、修改尾部及外部头部不符；覆盖结果须与原完整快照一致，所有合成记录不能冒充真实前瞻。

## 本地工具

初始化一个不存在的新目录：`python3 -m verify.paper_scan_archive init --archive <新目录>`。首条追加以 `--previous-seq -1 --previous-head GENESIS`，后续追加使用上次输出的序号和头部，并提供对应的前一行情目录：

```sh
python3 -m verify.paper_scan_archive append --archive <归档目录> \
  --scan <原扫描JSON> --receipt <原回执JSON> --market-dir <本次行情目录> \
  --previous-seq <上次序号> --previous-head <上次SHA256> --previous-market-dir <上次行情目录>
```

首条不填写 `--previous-market-dir`。归档不删除任何原始行情，追加时只检查调用方指定的前一头部和原始行情，未逐次重验更早的完整链。保存返回的头部并自行独立保管；文件保存在同一目录不构成可信外部锚。

中断或提交结果不明时，先运行 `python3 -m verify.paper_scan_archive status --archive <目录>` 查看最后已发布序号、头部及残留目录。该命令只检查提交元数据和扫描/回执，**不重建或验证行情差量**；不得将其称为恢复通过。指定原来保存的 `--expected-head <SHA256>` 可检测当前提交链不匹配，但不认证该预期值来源。

运行 `python3 -m verify.paper_scan_archive restore --archive <目录> --sequence <序号> --out <不存在的新目录> --expected-head <SHA256>` 顺序重建并校验该序号及其前置行情字节，原始扫描和回执一起复制；该操作不核验该序号之后的行情载荷。运行 `python3 -m verify.paper_scan_archive audit --archive <目录> --events <事件目录> --start <UTC起点> --as-of <UTC检查时间> --expected-head <SHA256>` 逐条恢复内存中的原始字节并调用连续覆盖核查，不在磁盘生成所有完整快照；输出会标实际恢复了多少条，提前失败时不能称为全链通过。均不创建定时任务或启用前瞻。
