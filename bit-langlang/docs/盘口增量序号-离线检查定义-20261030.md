# 盘口增量序号的离线检查：事前定义

研究用途：对已经保存的一份 Binance USDⓈ-M ETHUSDT 深度快照 `lastUpdateId` 和同一连接按接收顺序保存的增量消息，检查快照接合与 `pu` 链，发现明确断档。工具只做离线计算，不连接 WebSocket、不下单、不重建订单簿，也不启动平台策略。

[官方本地订单簿说明](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/How-to-manage-a-local-order-book-correctly)规定先缓冲增量并获取快照，丢弃 `u < lastUpdateId` 的旧事件，首个处理的事件满足 `U <= lastUpdateId <= u`，后续消息的 `pu` 等于前一条的 `u`；不满足时应重新初始化。本检查以此为基础，并额外保守要求后续 `u` 严格递增；这是一项本地筛选规则，不假称交易所承诺每次必然递增。

输入 JSON 只接收 `schema=paper-depth-sequence-v1`、`symbol=ETHUSDT`、`snapshot_last_update_id` 和 `events` 数组，每条是同一已保存连接的原始 `e=depthUpdate`、`s=ETHUSDT`、整数 `U/u/pu`；若存在 `st` 则必须为 1。事件不允许负数、布尔数、首末反序、其他合约或数据流。缺首个桥接事件标 UNKNOWN；桥接失败、链条中断或序号倒退标 GAP，并报告首个错误索引与有效前缀；畸形输入标 INVALID。首个桥接事件的 `pu` 不必等于快照 ID。即便序号连接也仅是 PARTIAL，不证明真实接收未丢首尾消息、时钟、来源、实际盘口或连续止损触发。离线 JSON 的哈希与源文件均须保留；本工具没有证据认证能力。

需用合成数据测试：首事件桥接、旧事件丢弃、断链、重复/倒退、缺桥、跨标的和伪造类型。实测网络、捕获持久化、快照价量重建、断线恢复和持仓风控串联不在本阶段完成范围。
