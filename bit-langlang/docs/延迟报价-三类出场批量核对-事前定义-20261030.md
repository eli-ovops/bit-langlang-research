# 延迟报价候选：三类出场批量核对事前定义

目标是将止损、EMA20 和 30 天到期这三种已定义的**假设出场**，统一接到同一种逐笔账本、报价中间价成本分解和资金费核对，再对一批提供的已平仓记录作一致性检查。不得改变冻结配置、原始下一根开盘模型或平台策略；本工具不启动观察、不交易。

- 止损先依 `paper_quote.assess_round_trip` 检查信号、入场、独立 bid 触发观察和出场报价的因果顺序、条件、深度及假设成交价；触发只是离散 bid 快照，不能声称连续监控或实际成交。
- 按该候选的 30 天持仓上限，若止损观察发生在到期之后，返回执行规则不匹配；若观察与到期同刻，或观察在到期前而出场决定在到期时刻或之后，先后/处理返回 `AMBIGUOUS_ORDER`。即使这些时间满足，也不能证明更早的 EMA 或止损信号没有遗漏。
- 所有出场共用同一逐笔账检查：入出场事件与账本编号、时刻、数量、价格及 0.4% 理论止损一致；以入场 ask、出场 bid 为账本参考，分别乘假设滑点，核对 5bp/边手续费、有符号资金费、净盈亏和净 R。双边点差相对两个报价 mid 单列，滑点不重复扣；资金费需要该笔覆盖快照，边界或缺失显式保留不确定状态。
- 批量检查须逐笔绑定证据和账本：重复或遗漏交易编号、证据或报价无效、未经核对的其他记录不得静默跳过；不允许把一个交易的成本数值或资金费凭证用于另一交易。保留每笔状态，任何 INVALID / STOP / 未知不能汇总成通过；即使全部形式相符也只能返回 PARTIAL，不代表完整账本或可执行结果。
- 资金费、跨交易并发、未平仓、组合权益和信号覆盖仍使用相关全账本检查，批量单笔对账不替代它们。批量成本比例以各笔正的 mid 参考毛盈亏之和为分母，分母不为正则 UNKNOWN；净 R 按各笔风险计算后做等权平均，不能直接用总盈亏除以风险之和冒充平均 R。
- 单笔费用核对不将该笔 `equity_at_entry` 与初始 2000U 强行相等：该笔前可能已有盈亏，缺完整账本时标 `UNKNOWN_REQUIRES_FULL_LEDGER`。批量检查仍用所提供的完整已平/未平账本进行已有的条件性权益与组合风险核对；账本是否真正完整依然未知。
- 结果保留来源哈希及时间；测试必须包含止损与 EMA 或到期混合、费用/符号、缺凭证、重复或缺失项、多个净 R 权重不同、同刻风险及失败优先级。所有样本均合成，禁止把合成测试写成前瞻记录。实际交易所和费用仍 UNKNOWN。

## 工具与清单

单笔止损用 `python3 -m verify.paper_stop_exit --signal <事件> --entry <事件> --entry-quote <报价> --mark <触发事件> --trigger-quote <触发报价> --exit <事件> --exit-quote <报价> --ledger <单笔CSV> --funding <该笔明细CSV> --schedule <资金费快照目录> --start <UTC起点> --as-of <UTC检查时刻>`。未提供资金费覆盖快照返回 `UNKNOWN_FUNDING`；不核实账户或实际订单。

批量清单格式如下，路径相对于清单文件；所有 `signal`、`entry`、`mark`、`exit` 引用的事件也必须出现在共同事件目录。`entries` 包含已平仓和未平仓记录的入场报价；`exits` 恰好覆盖已平仓编号。示例为结构说明，不是实际数据：

```json
{
  "schema": "paper-exit-batch-v1",
  "entries": {"t1": "entry-quote-1.json", "t2": "entry-quote-2.json"},
  "exits": {
    "t1": {"kind": "bid_stop", "signal": "events/signal-1.json", "entry": "events/entry-1.json", "mark": "events/mark-1.json", "trigger_quote": "trigger-1.json", "exit": "events/exit-1.json", "exit_quote": "exit-quote-1.json"},
    "t2": {"kind": "ema20", "signal": "events/signal-2.json", "entry": "events/entry-2.json", "observation": "observation-2.json", "scan": "exit-scan-2.json", "market": "exit-market-2.csv.gz", "exit": "events/exit-2.json", "exit_quote": "exit-quote-2.json"}
  }
}
```

`max_30d` 与 `ema20` 的字段相同，但不需要 `scan` 和 `market`。运行：

```sh
python3 -m verify.paper_exit_batch --scan <信号扫描JSON> --events <事件目录> --market-dir <信号行情目录> \
  --closed <全体已平仓CSV> --open <未平仓CSV> --funding <全部资金费明细CSV> \
  --manifest <批量清单JSON> --schedule <覆盖全部记录的资金费快照目录> --start <UTC起点> --as-of <UTC检查时刻>
```

返回包含逐笔核对、整体风险、条件性权益、资金费和输入哈希；有未平仓时结果最多 `PARTIAL_WITH_OPEN_UNKNOWN`。若模型条件权益非正，批量状态为 STOP；这只是一项条件性纸面判定，不触发平台 start/stop。
