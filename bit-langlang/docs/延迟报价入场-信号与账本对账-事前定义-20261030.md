# 延迟报价入场：信号与账本对账事前定义

目的：将既有冻结信号、人工事件、行情快照、延迟入场报价与已提供的纸面持仓账本串联，研究可观察入场证据；不把延迟报价候选冒充原来的下一根开盘执行，不注册或启动前瞻。

沿用 `延迟报价研究-事前定义-20261030.md` 的时间、一级报价和假设入场规则。对每个已记录入场：先由既有 `signal_reconcile` 重算候选和事件链，再以交易编号一一关联已平仓或未平仓账本的数量、事件以及独立报价文件；使用 `paper_positions_reconcile` 核对账本价格、时间、持仓和风险，并用 `paper_quote.assess` 检查报价时间、深度与假设价。信号和入场必须有真实顺序；同一份报价不得供不同入场重复使用。报价索引、事件、账本或行情缺失、额外项、重复项、无效或对不上都不能给出通过。

原信号核对器应继续显示 `EXECUTION_MODEL_MISMATCH`，新对账器另行标注 `PARTIAL_CANDIDATE_NOT_REGISTERED`，最多说明本地输入的形式关系；不改变冻结配置或原判定。若没有入场记录，结果标 `NO_ENTRY_EVIDENCE`。风控 STOP、过期、顺序不明、缺深度、无效输入优先呈现，不可包装成成功。

该候选尚未证明持续采集、未漏信号、报价真实性或真实成交，也未完成所有止损、EMA/到期出场、资金费及账户权益的端到端对账；历史 5 分钟开盘研究不能声称是该盘口执行模型的回测。任何真实起点、连续观察以及平台策略 start/stop 均未在此发生。

## 工具使用

将报价索引另存为 JSON 对象，键为交易编号、值为相对索引文件的报价 JSON 文件路径，例如 `{"paper-1":"quote-1.json"}`。使用下列命令检查提供的文件；输出记录输入文件哈希，最多为 `PARTIAL_CANDIDATE_NOT_REGISTERED`：

```sh
python3 -m verify.paper_delayed_signal_reconcile \
  --scan <扫描JSON> --events <事件目录> --market-dir <快照目录> \
  --closed <已平仓CSV> --open <未平仓CSV> --quote-index <报价索引JSON> \
  --start <实际UTC起点> --as-of <实际UTC检查时间>
```

缺少报价返回 `UNKNOWN_QUOTE_COVERAGE`，提供多余映射或复用同一次报价返回 `INVALID`，纸面保证金缺失或可见深度不足依检查结果返回对应状态。无事件不能被解释为成功覆盖；即便状态为 PARTIAL，也仍须独立核查完整行情、出场、资金费、估值、时间和风险。
