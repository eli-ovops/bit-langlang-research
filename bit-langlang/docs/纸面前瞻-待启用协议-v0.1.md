# TPH 冻结规则：纸面前瞻待启用协议 v0.1

状态：**草案 / 未开始 / 不得自动 PASS**。人工记录的信号采集发生在收盘后，不能据此声称已按同一瞬间的下一根开盘价入场；如采用稍后的价格，执行规则与现有冻结回测不同，须先单独定义、冻结并验证，当前版本尚不能作为可执行前瞻启用。本文件是准备材料，不是创建策略、启动观察、下单或投入资金的指令；任何平台策略 start/stop 前按用户要求先报告。当前账号、真实手续费、保证金模式、标记价格和真实滑点 UNKNOWN。

后续研究补充：本地延迟报价候选的入场形式对账见 [信号与账本对账定义](延迟报价入场-信号与账本对账-事前定义-20261030.md)。它不替代本协议的 `EXECUTION_MODEL_MISMATCH`，也尚未覆盖候选执行模型的全部出场及持续观察。

## 1. 目标与对象

以未被回填的观察记录检验现有冻结规则能否在假设成本下产生可复核的纸面结果，区分信号完整性、执行一致性与净表现。冻结文件为 `verify/frozen_config.json`；哈希随每次扫描及事件记录。原规则对 BTC 自比较恒为 0，故**此版本有效候选仅 ETHUSDT 多头**。BTC H1 是另一份历史探索，不纳入此版本。

单笔初始价格风险 0.15%，每日最多新开 3 笔，同时最多 3 笔，名义杠杆最高 5 倍。0.4% 是入场到止损的价格距离；它不是实际最大亏损保证。发生跳空、手续费、资金费或滑点时实际亏损可能超过该距离。

历史回放使用固定 5 倍、逐仓保证金的研究代理；真实交易所及账户的杠杆设置和保证金模式仍为 UNKNOWN。纸面账本可填写 `margin_at_entry`（入场时为该笔分配的模拟初始保证金，USDT），用 `entry × qty / margin_at_entry` 检查纸面初始名义倍数，超过 5 倍则报告 STOP/ALERT。缺失时标记 `UNKNOWN_INCOMPLETE`，不当作合规；非正数或非法值为 INVALID。该比例是本研究的简化检查，并不能证明平台所选杠杆或真实保证金，实际交易所规则、价格与逐仓/全仓处理可能不同。Binance 的相关说明中，保证金要求还涉及标记价格、挂单和持仓模式：[Binance Futures 保证金计算说明](https://www.binance.com/en/support/faq/detail/4f83b65d83654b5e933f85ef12bf769d)。

## 2. 假设、数据与未知

建议研究口径：单边手续费 5bp、单边不利滑点 2bp、历史资金费逐次计入；纸面价格为参考价格应用假设滑点后的价格，双边手续费、资金费用 USDT 单独记账，避免再次扣滑点。此口径只是假设，交易所/账户实际成本 UNKNOWN；费用、资金费或价格无法获得时填 UNKNOWN 并返回 INVALID，不以 0 代替。保留资金费率、时间及价格来源；同一 K 线内先触发止损还是结算资金费若无法确定，单独标示并作敏感性检查。

行情必须是连续、已收盘且新鲜的 BTC/ETH 5m，UTC 网格对齐，预热不少于 205 天；205 天是最低数据门槛，非 EMA 消除初始化影响的证明。保存快照来源和哈希；`scripts/11_stage_recent_market.py` 只准备 5m 数据，不更新资金费。旧 `scripts/02_download_market.py` 的最后一根未收盘 K 线问题未修，不可直接拿其历史末根做前瞻。

扫描入口还要求 BTC 与 ETH 的完整已收盘时间网格一致；仅最新 K 线时间相同不足以通过，历史起点不同返回 INVALID。[两币历史网格核验](前瞻扫描-两币历史网格一致性-核验结果-20261030.md)

如以后需要单次扫描覆盖整个已注册观察区间，可在 `paper_scan_once` 指定 `--cover-since <实际UTC起点>`，自动扩大候选窗口并核查起点前预热；其默认 `--days 3` 不能覆盖超过 3 天的整段观察。[候选起点覆盖核验](前瞻扫描-候选起点覆盖-核验结果-20261030.md)；这不等于连续前瞻已经开始或长期运行已经验收。

信号依据 K 线收盘才能判断，下一根开盘是理想化模拟参考，不保证现实能以该价成交。不得将事后知道的价格、历史回填、合成数据或账户真实订单混入前瞻记录。

扫描记录的 `reference_stop_on_open` 仅为未计滑点的参考开盘价乘以 0.996，并非纸面仓位的止损价。纸面入场价一旦记录，应以该模拟成交价乘以 0.996 得到未取整的理论止损；实际价格精度、触发类型和成交不确定，不能假称已挂单。`signal_reconcile` 按记录的入场价另输出该理论值。旧扫描文件里的 `stop` 字段与新字段口径不同，不可直接复用；旧快照仍保留供追溯。

## 3. 记录与对账

1. **启用之前**确定实际 UTC 起点、固定配置哈希、行情/资金费来源、模拟成交与费用假设、结束和审核方法；不得倒填。建立只属于本次观察的新目录，原始快照和事件保留。
2. 每个候选记录 signal，再对应一次 entry 或明确原因的 skip；事件由 `verify.paper_event` 保存，须带信号 K 线开盘时间、手动采集时间，entry/exit/mark 还带交易编号与模拟价。不得把信号采集前的理想开盘时刻写成已知信号后的入场；记录较晚的模拟入场仅为候选执行口径，不等于当前冻结的下一根开盘模型。采集延迟、系统时钟、实时价格来源及其采集时间另核。工具不下单、不证明记录未伪造。
3. 保持纸面未平仓快照（`verify/templates/forward_open_v1.csv`），带价格来源、最新时间、已付费用与资金费；用 `verify.forward_open` 审查。价格超过 15 分钟、来源不明、余额不完整或疑似触损时停止生成可操作结论，未平仓净值/真实强平不得猜测。某一笔过期不会遮住另一笔新鲜报价已低于止损的 ALERT；这只是输入价格告警，不证明交易所触发或成交。多笔报价时间不同时，浮盈亏之和是各时点评估值的求和，不是同步组合估值。
4. 平仓后在新 CSV（`verify/templates/forward_paper_v1.csv`）保留实际采用的模拟入出价、数量、入场权益、双边手续费与带符号资金费、纪律字段；`verify.forward_report --file <CSV> --start <实际UTC起点>` 计算净 R 与初始价格风险。入出场均已包含模拟滑点，不再二次扣除。另记录事前约定的入场、出场参考价及来源 `reference_entry`、`reference_exit`、`reference_source`；每笔均有这些数据才能估算滑点及完整成本比例，否则比例 UNKNOWN，净 R 仍可由成交价计算。参考价须可追溯、可在相应时点获得；填写来源不等于来源已核实。
5. 用 `verify.paper_reconcile` 对照事件与交易编号/时间/价格；用 `verify.signal_reconcile` 重算每次扫描窗口的全部候选并匹配 signal + entry/skip。还需独立确认扫描窗口连续、空档、系统时钟、原始文件完整性及持仓余额；任何 PARTIAL 只能表示形式一致。
   连续扫描核对还需查看 `signal_availability_status`：人工信号事件若不晚于候选首次扫描回执，无法由该扫描证明当时信号已可用，标 UNKNOWN；严格晚于也仅代表记录时间有序，不能证明实际读取或排除回填。详见[首次可见时间补充核验](纸面信号首次可见时间-补充核验-20261030.md)。
   批量对账以其 `as_of` 为事件检查上限，允许扫描生成后形成的候选事件；连续扫描封存仍按每次扫描时点处理。是否确实在信号发生前取得扫描回执仍须单独核对。[扫描后事件时间口径](扫描后事件对账-时间口径修复-20261030.md)
   信号、入场或跳过的采集时刻不得晚于信号 K 线收盘后 15 分钟；信号采集时刻必须早于决定的事件时间和采集时间，否则 INVALID；相同时间返回 AMBIGUOUS_ORDER，不同入场不得共用交易编号。信号收盘后的延迟入场返回 `EXECUTION_MODEL_MISMATCH`，因为冻结规则指定下一根开盘；它不是通过，也不会自动改变冻结配置。15 分钟仅是记录时效上限，不能证明价格可成交或记录没有回填。
   如最新信号之后的下一根 K 线尚未收盘，扫描快照没有下一根历史开盘参考价，结果提供 `pending_reference_count` 而非零差价；待该 K 线收盘并取得新快照可再次核对。存在延迟入场时，整体状态优先显示 `EXECUTION_MODEL_MISMATCH`；两种状态都不能证明参考开盘价实际可成交。
6. 用 `python3 -m verify.paper_risk_audit --closed <已平仓CSV> --open <未平仓CSV> --start <实际UTC起点> --as-of <实际UTC检查时间>` 联合检查已记录的每日入场数、同时持仓数及同时持仓初始价格风险之和的峰值；缺文件返回 UNKNOWN，重复交易编号无效。同一时刻同时有入场与出场而缺少更精确顺序时，分别给出先出后入与先入后出的并发和初始价格风险峰值上下界；下界已超限为 STOP，否则返回 `AMBIGUOUS_ORDER`，并另标并发上下界是否跨越限额，不能以较小值认定实际发生的并发。若另有明确 STOP 或价格过期，状态优先呈现 STOP 或 STALE，但同时保留同刻不确定标志。风险之和不是当前浮亏或最大可能损失，合并后的结果仍不能证明账本完整，也不能证明现金、组合权益或强平价格。
   同一工具还对记录中入场前没有其他仓位的时点核对 `equity_at_entry`：假定初始 2000U、账本完整、没有出入金或遗漏费用，以此前已平仓净盈亏计算模拟入场前权益，差额绝对值超过 0.01U 返回 `MISMATCH_ASSUMED` 并在纸面风控中 STOP；这表明输入与该假设不一致，不证明真实账户发生违规。若持仓重叠、多个入场同刻或先前出场恰在同刻，标 `UNKNOWN_OVERLAP_OR_ORDER`，不能用缺少的同期估值猜测。匹配也不能证明实际余额或漏记情况。
   再运行 `python3 -m verify.paper_positions_reconcile --closed <已平仓CSV> --open <未平仓CSV> --events <事件目录> --start <实际UTC起点> --as-of <检查时间>`，核对已平仓与未平仓各自的入场事件，以及出场事件或最新估值事件。缺失、重复、价格不匹配或入场/估值/出场采集顺序倒置返回 INVALID；事件时间或采集时间相同且无法判断先后返回 AMBIGUOUS_ORDER。此检查不替代第 5 步的信号完整性核对，最多 PARTIAL，也不证明用户账户或持仓完整。
7. 资金费明细使用 `verify/templates/forward_funding_v1.csv`，保留每笔交易、资金费时间、费率、参考标记价、数量、有符号费用和来源。用 `python3 -m verify.funding_reconcile --closed <已平仓CSV> --open <未平仓CSV> --funding <资金费CSV> --start <实际UTC起点> --as-of <实际UTC检查时间>` 检查金额公式与账本逐笔合计。多头的费用以 `数量 × 参考标记价 × 资金费率` 估算，正数为支付、负数为收到；价格须注明来源，公开标记价不等于实际账户结算价。
   工具将资金费时间距离入场或出场不超过 60 秒作为研究性模糊区间，返回 AMBIGUOUS；实际交易所的结算时间、账户是否被计费仍须核实。快照结束时间为右端不包含，因此要证明覆盖出场或估值时刻后整整 60 秒的边界，`end_utc_exclusive` 必须严格晚于该边界；恰好等于边界时返回 UNKNOWN。记录为零且没有对应明细或可核对的覆盖快照时返回 UNKNOWN，不能推断没有发生结算；已提供明细校验一致也只能得到 PARTIAL，不证明没有漏项。STOP 只表示记录中已发现的风险问题，不触发平台操作。
8. 如使用 Binance 公开数据作研究参考，可一次性运行 `python3 scripts/12_stage_funding.py --start <UTC起点> --end <UTC终点> --outdir <不存在的新目录>` 采集区间 `[start,end)` 的 BTC/ETH 资金费公开响应；不会访问账户或更新旧文件。随后给上一步命令附加 `--schedule <新目录>`，形式核对文件哈希、时间覆盖、费率与参考价，并检测覆盖窗口中明确缺失的结算明细。收盘仓位需要覆盖至出场后 60 秒；未平仓费用核对截止其 `mark_time`，参考快照须覆盖到该时刻后 60 秒，之后至检查时刻的费用仍为 UNKNOWN。请求后的服务器时间或本地采集完成时间晚于检查时刻无效。旧版 v1 只记请求前时间，不能证明采集已完成，因此拒绝用于覆盖检查。若已覆盖且区间内无结算，零费用可形成 PARTIAL 形式结果，但来源、实际账户交易所、缺漏及结算过程依然未知。快照需在正式观察时另行采集；历史示例不可回填为前瞻。
9. 可运行 `python3 -m verify.paper_equity --closed <已平仓CSV> --open <未平仓CSV> --start <实际UTC起点> --as-of <实际UTC检查时间>` 计算条件性纸面组合权益：假设初始 2000U 和完整账本，将估值时刻前的已平仓净盈亏，加上当时未平仓价格盈亏，减去记录的入场手续费和有符号资金费。估值时间取所有未平仓记录共同的报价时间；不同步，或有其他已平仓交易在该时仍持有/恰在该时平仓且缺少同期估值时，返回 UNKNOWN。估值时刻之后的交易不计入；无持仓时估值截至最近平仓时间。输入触及风控或模拟权益非正时返回 STOP；该数值仍依赖无出入金、无其他资产、无遗漏费用或额外强平损失等未经证实的假设，入场时权益也未独立对账。估值后的资金费和交易、现金余额、真实权益及强平均 UNKNOWN；REVIEW 不是 PASS，不替代前述独立对账。

## 4. 判定及停止边界

现有冻结阈值保留：任意纪律违规，或至少 20 笔且均净 R < -0.2，纸面评估应 STOP；90 天、20 笔、净 R >0、成本/毛利 ≤30% 是历史数值门槛，但原始分母口径不明确。当前报告单列试验口径：多头参考价毛 PnL = `(reference_exit-reference_entry)*qty`，滑点成本 = 参考价毛 PnL − 成交价毛 PnL，完整估算成本 = 手续费 + 有符号资金费 + 有符号滑点，分母为各笔正的参考价毛 PnL 之和。收到资金费或有利滑点可为负；分母为零或参考价缺失则比例 UNKNOWN。该口径与历史门槛的对应关系未经确认，只显示候选数值判断，不自动 PASS。真实费用、联合持仓、未平仓权益、记录真实性、连续覆盖、成交假设及研究多重选择未核清前，不宣称可投钱。报告中的 STOP 是纸面判定，不会自动停止任何平台策略。

## 5. 尚缺验收

- 实际起点未设置；无真实前瞻记录，也无持续观察机制。
- 扫描/事件/账本及条件性组合权益的合成链路已测试；持续数据、漏信号、真实组合权益与实际成本未端到端验收。
- 已平仓报告只检查已平仓记录中的每日开仓和并发上下界；联合工具会加入给定的未平仓快照，但两者都无法检查漏记。同刻先平仓后开仓与先开仓后平仓分别作为下界及上界，不证明先后顺序；同一笔入出场时间相同时需提供更精确时间，否则 INVALID。须结合事件和原始来源单独核对完整性及总风险。
- 下一根开盘参考价、标记价、强平及账户实际费率均不能证明为可实现价格。
- 现有冻结执行规则与人工信号采集在时间上存在冲突；必须单独定义实时可观测价格及采集证据、延迟执行口径和对应历史对照，完成对账后才能考虑新的纸面前瞻版本。既有下一根开盘的回测及其结果保留为理想化基线，不得混称同一种执行。
- 要比较方法改进，另写独立候选、冻结新版本与新起点；不得更改或混算原版本。
