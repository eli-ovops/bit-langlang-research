# 批量对账与未平仓盘口会话：联检结果

`verify.paper_exit_batch` 的现有清单新增可选 `depth_sessions` 数组，元素为相对于清单所在目录的已保存盘口会话目录，例如 `"depth_sessions": ["depth-session-1", "depth-session-2"]`。原共同信号/入场事件和账本对账仍先执行，盘口会话使用相同未平仓账本与检查时刻；独立原始文件和会话归档须通过已有检查。若没有提供会话，返回 `UNKNOWN_NOT_PROVIDED`，不能视作行情完整。

合成端到端测试串联信号、两笔入场、一笔已平仓和一笔未平仓：即使该未平仓的另一份单次报价证据被故意改坏，只要有效盘口会话在其入场后已观察到买一不高于止损，整体报告为 STOP，并保留损坏证据的 INVALID；已平仓平均净 R 仍在 `risk_check.closed` 明细中。内存调用及命令行清单均经过验证，相关 10 项测试通过。若没有已观察触损，不能由本检查推断未触损，缺口、批内变化和真实成交仍 UNKNOWN。

这些是虚构交易及合成盘口事件，不是正式前瞻、真实订单或账户状态。STOP 是纸面报告状态，不执行平台操作。本次没有启动或停止平台策略；规则及限制见[联检定义](批量对账-盘口会话未平仓联检定义-20261030.md)。
