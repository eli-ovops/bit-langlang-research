# 前瞻长窗口单次扫描：离线测量结果

在本机使用已保存的 BTC/ETH 历史行情，以 2026-10-25 00:00 UTC 为假定检查时刻，各执行一次本地扫描：

| 候选窗口 | 扫描函数壁钟耗时 | JSON 序列化大小 | BTC / ETH 候选 |
| --- | ---: | ---: | ---: |
| 3 天 | 0.805 秒 | 1,528 字节 | 0 / 0 |
| 90 天 | 0.769 秒 | 13,566 字节 | 0 / 93 |

这是按 3 天、90 天顺序各跑一次，第二次可能受文件缓存影响，不能由此断言长窗口更快。90 天 ETH 候选数与先前独立月度统计的 8 月 30 个、9 月 63 个合计一致；这些是历史候选，不是前瞻入场或成交。两次扫描的整体 `validation_status` 均为 `INVALID`，因为现有冻结配置的 BTC 自比较和端到端执行条件尚未解决，不能把候选数当作策略通过。

测量仅覆盖本地 `build_snapshot`；未包含网络采集、原始行情追加和压缩、报价与资金费、保存回执、归档与恢复，也未测峰值内存和长时间连续运行。因此这些数字不足以证明五分钟周期持续运行或 90 天磁盘容量可靠。输入哈希、完整测量和未覆盖项见[机器可读结果](../data/verify/offline-scan-window-benchmark-20261030-01.json)，口径见[测量定义](前瞻长窗口单次扫描-离线测量定义-20261030.md)。没有启用任务或平台策略。
