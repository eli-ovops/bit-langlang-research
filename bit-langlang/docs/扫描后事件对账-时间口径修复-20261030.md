# 扫描后事件对账：时间口径修复

单次扫描先生成结果，之后人工才能记录 signal 和 entry/skip。原 `signal_reconcile` 固定要求所有事件在扫描生成时间以前已采集，因此对扫描后正常记录的事件可能误判 INVALID，即使它们不晚于实际检查时间。

现增加可选 `evidence_as_of`：未指定时保持原严格行为；延迟报价批量对账明确传入自己的 `as_of`，允许已在该扫描候选内的事件在扫描生成之后记录，同时仍要求事件不晚于检查时刻、在信号收盘后规定时间内采集，且 signal 采集早于决定。检查时间不能早于扫描生成或晚于当前时间。扫描候选本身始终只用扫描生成时已收盘的数据，不能用之后的行情回填。

连续扫描归档封存检查不传新参数，仍以每次扫描生成时可见的事件进行逐段严格封存；新尾段继续待封存。一次扫描无法证明其文件在人工信号发生前已经可用，仍须用扫描保存回执与 `paper_scan_coverage` 的首次可见时序等证据检查；来源、时钟和回填风险仍 UNKNOWN。此修复不将延迟报价入场改称为冻结的下一根开盘成交。

合成测试覆盖扫描后、检查前记录的正常事件，以及检查时刻之前未记录或检查时间早于扫描生成时的拒绝。其结果只证明离线形式对账，不证明实际前瞻、真实成交或连续观察。
