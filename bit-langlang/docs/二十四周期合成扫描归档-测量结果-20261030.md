# 24 周期合成扫描与归档：测量结果

以时间平移的历史价格和合成追加 K 线，离线压缩演练了 24 个 5 分钟扫描周期；扫描与归档使用项目代码，扫描时间及回执时间使用合成时钟。没有连接网络或交易账户，也没有真实等待两个小时。

| 本次样本 | 结果 |
| --- | ---: |
| 单周期壁钟耗时中位数 / 最大值 | 1.602 / 1.754 秒 |
| 24 条归档完整重建并核对 | 6.628 秒 |
| 初始两币行情文件 | 约 4.57 MB 逻辑大小 |
| 24 周期后归档目录 | 约 5.43 MB 逻辑、5.88 MB 已分配 |
| 演练全部临时文件（含源、每次完整输出和归档） | 约 120.13 MB 逻辑大小 |
| 其中 24 次完整输出目录 | 约 110.13 MB 逻辑大小 |

归档审计为 `PARTIAL_COVERAGE_UNVERIFIED`，24 条均已重建；合成期间没有已封存候选，最新约 920 秒仍未封存。因没有产生新候选，此次不能证明有信号时的完整记录或逐笔对账；这部分另见[合成交易链路演练](前瞻扫描与逐笔报告-证据关联核验-20261030.md)。

结果显示，保存全部中间完整输出的空间需求值得在长期方案中单独考虑；归档目录本身较小，不代表可自动删除这些文件或已证明释放空间。此次临时目录由测试创建并在结束时清理，既有历史行情哈希未改变。候选、压缩率、运行耗时均取决于数据和环境；24 个离线合成周期不能外推 90 天容量或连续可靠性，也不包含真实网络、报价和资金费采集。

逐周期耗时、保存字节数及哈希见[机器可读结果](../data/verify/synthetic-24cycle-benchmark-20261030-01.json)，方法见[测量定义](二十四周期合成扫描归档-测量定义-20261030.md)，可重复的合成演练代码为 [synthetic_24cycle_benchmark.py](../verify/synthetic_24cycle_benchmark.py)。
