# 盘口逐条落盘回执：离线定义

问题：已有归档只保存消息接收时刻，不能证明该消息文件何时写完。新增独立 v2 归档：每条事件写入、文件与目录 fsync 完成后，读取本机 UTC 时间，生成包含事件文件哈希、事件序号和前一回执哈希的回执文件，再对回执及目录 fsync；仅在该文件与目录 fsync 返回后向调用者报告成功。

回执记录的 `event_fsync_returned_at_utc` 是本机在事件写入与目录 fsync 返回之后读取的墙上时间，不是交易所时间、不可证明物理介质已经持久化，也不是回执文件自身 fsync 完成时刻。若本机时间早于声明的接收时间则拒绝；本机时钟真实性及进程真实意图仍 UNKNOWN。对外不能称为已实际触发或成交。

事件与回执分别从 0 顺序存储并各自建立哈希链；封存绑定两条链头及条数。丢失、篡改或半写入回执时不得把该事件当作可确认前缀；未封存、缺外部锚点、系统崩溃和整套重写均不能证明完整性。新 v2 与既有 v1 分离，不更改旧归档或已保存预检。

先离线合成验证成功、回执写入失败、时钟回退、篡改/缺失/截断及未封存恢复；再把已有公开样本离线写入 v2 进行往返核对。该回放是在消息原始捕获之后生成回执，不能声称是当时实时落盘时间；真实流接入和实际吞吐需后续单独验证。本次不连接账户或行情，不启动/停止平台策略。
