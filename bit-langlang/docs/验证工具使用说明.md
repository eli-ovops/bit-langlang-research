# 验证工具包使用说明（verify/）

> 2026-10-30 勘误：成本达到某个 R 值不能单独推出必亏；`0.2R` 是研究选择而非盈利必要条件，详见[成本表述勘误](成本与盈利能力-历史表述勘误-20261030.md)。

> 目的：把"复刻 bit浪浪 的道"从**文档**变成**可测量的行为**。
> 评价对象是**遵守率**，不是收益。工具不保证赚钱，只告诉你"有没有按规矩做"。

## 快速开始

```bash
cd /Volumes/EXTERNAL/bit浪浪

# 1) 成本门槛：假设费率和滑点下，止损距离如何影响成本与风险之比
python3 -m verify.cost_model

# 2) 历史回放：按纪律卡条件，历史上每天会有多少警报（评估 5m 手工可行性）
python3 -m verify.replay --start 2025-01-01 --end 2026-10-25

# 3) 记一笔交易（或用模板 CSV 批量导入）
python3 -m verify.log add --date 2026-01-01 --symbol BTCUSDT --side long \
  --setup box_pullback --entry 90000 --stop 89100 --t1 92700 --exit 92700 \
  --qty 0.0002 --notional 18 --margin 2000 --fee -0.9 --slippage -0.2 \
  --risk_pct 1.0 --hold_min 45 --five_q_pass 1 --stop_placed 1 \
  --added 0 --reversed 0 --plan_deviation 0 --review_class 体系内

# 4) 看 KPI（行为遵守 + 交易指标）
python3 -m verify.kpi

# 5) 校验数据
python3 -m verify.log validate
```

## 模块与定义

### `verify/log.py`
逐笔日志（`data/verify/trades.csv`），字段见 `verify/templates/trades_template.csv`：
`date,symbol,side,setup,entry,stop,t1,exit,qty,notional,margin,fee,slippage,risk_pct,hold_min,five_q_pass,stop_placed,added,reversed,plan_deviation,review_class,note`

- `five_q_pass`：开仓五问是否全部通过（1/0）
- `stop_placed`：是否**开仓即挂止损**（1/0）
- `added/reversed`：是否加仓/反手（1/0，红线）
- `plan_deviation`：是否计划外交易（1/0）
- `review_class`：体系内亏损 / 逻辑错 / 纪律错

### `verify/kpi.py`
**行为 KPI**（核心）：
| KPI | 计算 |
|---|---|
| 五问完成率 | mean(five_q_pass) |
| 开仓即挂止损率 | mean(stop_placed) |
| 风险合规率 | mean(risk_pct ≤ 阈值) |
| 加仓/反手次数 | sum(added) / sum(reversed) |
| 计划外交易率 | mean(plan_deviation) |
| 最大连亏 | R<0 的连续段最大值 |

**交易指标**（参考）：胜率、期望 R、PF、最大回撤（固定风险）、费用/毛利比、按 setup/币种/方向分组。
> 注意：`R = 方向 × (exit−entry) / |entry−stop|`，是**风险单位 R**，不是保证金收益率。

### `verify/cost_model.py`
公式：`往返成本(bps) = 2×(fee_bps + slip_bps)`；`成本(R) = 往返成本 / 止损距离%`。
输出不同止损距离（0.2/0.5/1/2%）× 费率（2/5/10bps）× 滑点（0/5/10bps）的**盈亏平衡毛优势表**。
- 例：止损 0.5%、taker 5bps+滑点 5bps → 成本 = 0.4R/笔 → 你的毛优势必须 >0.4R 才不亏。
- 这是"薄优势策略"的生死线。

### `verify/replay.py`
按纪律卡条件（前低承接 + 5m 止跌 + 止损 0.2–1.2%）在 10 币 5m 上回放，统计：
- 每日警报数、每币每日警报数
- 止损距离分布
- 到 +2R / −1R 的 bar 数与比例
**只评估频率与延迟可行性，不是收益回测**（未计费用）。

## 已知局限

1. 回放不能替代人工执行：能出多少信号 ≠ 人能不能跟上。
2. 行为 KPI 依赖你如实填写；填假数据等于自欺。
3. 没有实现"滑点/成交概率"的真实撮合，成本模型是上界估计。
4. 没有 2024-07 之后的真实交易样本，无法验证"今天是否还适用"。
