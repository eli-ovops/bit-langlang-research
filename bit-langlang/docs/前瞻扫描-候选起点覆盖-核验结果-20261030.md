# 前瞻扫描：候选起点覆盖核验

原 `verify.paper_scan_once` 默认只让扫描文件保留最近 3 天的候选；若之后用该单份扫描核对从更早起点开始的全部逐笔账本，`signal_reconcile` 会正确拒绝窗口不足，但不能据此完成全期对账。尤其在 90 天观察设想下，默认 3 天不是可用的全期扫描窗口。

现增加可选参数 `--cover-since <实际UTC起点>`：必须为 5 分钟 UTC 网格且不晚于公开服务器时间；自动扩大 `--days` 的有效值，让保存的两币候选窗口覆盖该起点，并要求源行情在起点之前至少有 205 天连续预热。扫描保存后再次检查两币候选窗口确实覆盖起点；缺失或过晚则报错，**不写扫描回执、不追加归档**。返回的 `candidate_days_effective` 是此次实际要求扫描的天数，`candidate_cover_since_utc` 是指定起点。未指定参数时保留原 `--days` 行为。

这是一次性公开数据研究工具的参数，不是注册前瞻、运行定时器、创建策略或下单。未来如使用，应在已确定实际观察起点后指定该起点，不能用历史起点冒充前瞻；仍须核查每次扫描、连续覆盖、保存回执、未封存尾段、真实时钟和来源。205 天只是研究下限，并不证明 EMA 初始化误差已经消失；扫描窗口扩大后的长期磁盘、延迟及连续运行可靠性尚未验收。

合成测试覆盖起点前预热不足的拒绝、90 天覆盖自动扩窗、扫描文件窗口迟于起点或为 NaT 时拒绝回执，以及现有扫描/归档回归；全部不使用真实前瞻或平台策略。正式使用前仍须按[待启用协议](纸面前瞻-待启用协议-v0.1.md)处理执行模型不一致等缺口。
