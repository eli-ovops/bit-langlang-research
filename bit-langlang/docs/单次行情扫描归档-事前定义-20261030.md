# 单次只读行情扫描与归档：事前定义

目的：为后续纸面观察准备一条可重复调用的本地单次工作链，验证从两币公开行情到扫描、回执和不可覆盖归档的因果及恢复。此工作不创建循环、定时任务、持续监控或真实前瞻起点，不访问账户、不调用平台策略 start/stop、不下单；公开 Binance USD-M 仅是研究数据源，最终账户交易所及真实成本 UNKNOWN。

- 输入为调用方提供的两币不可变历史快照、运行新目录，以及可选的既有归档头部和前一行情目录。启动前验证输入文件哈希、时间网格和完整性；不得使用最后一根仍未收盘的数据作为基线。
- 仅请求公开服务器时间和 BTC/ETH 5 分钟 K 线；记录原始响应和本机请求/响应时刻，以服务器时间筛选已收盘 K 线。每币单次最多 3 页、每页最多请求 1000 根，超出范围即停止，不自动扩大请求。服务器时间须落在本机请求区间扩展的 ±2 秒内；时钟和来源仍未独立认证。K 线须连续、无重复、按 UTC 对齐且 OHLC 合法。
- 从基线最后一根开始重取，用该根 OHLC（以及基线存在时 volume/turnover）核对提供方当前值；若任何字段不一致则报告 `SOURCE_REVISION`，保留原件与响应，不能覆盖或悄悄替换。无需新增已收盘 K 线时返回 `NO_NEW_CLOSED_BAR`，不伪造新扫描和归档提交。BTC 和 ETH 的最新收盘时间不一致、缺口、过期或响应格式错误时失败。
- 有新增数据时在新运行目录写入两币完整快照，重算已收盘冻结信号并保存扫描 JSON，在其后生成本机回执；原始基线不可修改。按前次预期序号和头部追加增量归档，写入中断或重复处理时先查询已发布头部，不得以未知结果盲目重复提交。
- 每轮最多一次单次运行，允许恢复时由调用方显式指定已确认头部；本工具不自动决定信号、纸面仓位、事件或交易。扫描结果仅是公开行情的一次快照，`validation_status` 不能自动 PASS，不证明信号实时连续覆盖、盘口、资金费、实际保证金或撮合。
- 合成测试覆盖正常追加、尚无新 K 线、未收盘过滤、基线修订、缺口、两币不一致、时钟偏差、归档结果未知和重复提交。真实接口只做一次有限只读预检，若服务拒绝、收费或超出授权则停止，不换身份、代理或路径绕过。预检保存独立证据并明确 `PREFLIGHT_NOT_FORWARD`。

## 本地命令

`python3 -m verify.paper_scan_once --source <已有双币行情目录> --out <不存在的新运行目录> --archive <不存在的新归档目录>` 执行一次公开只读预检，默认查看 3 天候选。仅需快照而不归档可省略 `--archive`；无新收盘 K 线时不生成扫描或提交。既有归档追加时，需显式提供上一次已确认的 `--previous-seq`、`--previous-head`，并将 `--source` 指向头部对应的完整行情目录。

若结果为 `ARCHIVE_RESULT_UNKNOWN` 或进程中断，不得推断是否提交：先用 `python3 -m verify.paper_scan_archive status --archive <归档目录>` 查询最后已发布序号与头部、保留的残留，再决定如何恢复。该状态只核对元数据；完整字节和覆盖须另行恢复或核查。每次运行使用新目录，不自动覆盖或清理原件。
